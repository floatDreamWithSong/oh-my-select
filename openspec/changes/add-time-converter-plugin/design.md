## Context

时间转换器是本地插件体系中的第三个工具类示例，目标是把用户选中的时间戳或日期文本转成常用格式。它需要避免过度自然语言解析，尤其要拒绝年号、短数字和非法日期，防止无意义文本触发弹窗。

## Goals / Non-Goals

**Goals:**

- 接受 10 位 Unix 秒时间戳和 13 位毫秒时间戳。
- 接受常见格式化日期或日期时间字符串，带时区的按时区解析，不带时区的按系统本地时间解析。
- 拒绝空值、非字符串、普通短数字、年号、非法日期和任意自然语言文本。
- 输出 Unix seconds、milliseconds、ISO 8601 UTC、local date time、local date 和 RFC 2822。
- 弹窗展示源值、解析上下文、六行转换结果和逐行复制。
- 插件实现完全留在 `examples/plugins/time-converter` 内。

**Non-Goals:**

- 不把插件做成内置默认插件或自动安装插件。
- 不提供 settings 页面、storage 或外链能力。
- 不支持 `tomorrow`、`next Friday`、`2 hours ago` 等相对自然语言日期。
- 不接受除 10 位和 13 位以外的纯数字时间值。
- 不新增宿主剪贴板 bridge 或外部依赖。

## Decisions

1. 时间解析先做形状过滤，再使用原生 `Date`。
   - 选择：先识别 10/13 位数字、日期形状和时区形状，再交给 `Date` 并做有效性检查。
   - 原因：原生 `Date` 对自然语言和非法日期可能过宽，必须在 matcher 层保持保守。
   - 替代方案：完全依赖 `Date.parse`。会误接 `2026`、短数字或部分自然语言文本。

2. 日期字符串无显式时区时按系统本地时间。
   - 选择：`2026-04-28` 按本地午夜，`2026-04-28 10:30:00` 按本地时间。
   - 原因：用户从本地文档中选择的无时区日期通常期待本地解释。
   - 替代方案：统一按 UTC。会让本地日期时间输出不符合用户直觉。

3. 输出值保持机器可读而非本地化。
   - 选择：标签本地化，值使用稳定格式如 `YYYY-MM-DD HH:mm:ss`、`YYYY-MM-DD`、ISO 和 UTC string。
   - 原因：这些输出通常用于复制到代码、接口或日志检索。
   - 替代方案：使用系统 locale 字符串。格式会因环境变化而不稳定。

4. 无 settings 的轻量插件包。
   - 选择：不提供自定义输出行或时区设置。
   - 原因：首版重点是覆盖主流程和复制交互，避免引入 storage。
   - 替代方案：增加时区 presets 和输出偏好。可作为后续扩展。

## Risks / Trade-offs

- 原生 Date 在不同环境对字符串支持有差异 -> 通过形状过滤、非法日期 round-trip 和样本测试收窄行为。
- 无时区输入可能在不同时区得到不同 UTC 输出 -> 这是本地时间语义的预期结果，弹窗需展示解析上下文。
- 长 RFC/ISO 文本可能撑破弹窗 -> 行值视觉截断并用 `title` 保留完整值。
- 剪贴板路径可能被 sandbox 限制 -> 保留浏览器 clipboard 与 textarea fallback，并手动验收。
